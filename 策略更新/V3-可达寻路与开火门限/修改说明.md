## 修改依据

依据有两部分。一是本地会话对 V2 实战对局19～28 的分析，见 [交接/2026-11-24-分析结果.md](../../交接/2026-11-24-分析结果.md)；这十局原始日志只在用户本机，没有推送到仓库。二是本次在仓库已归档的对局01～18日志和地图上复核的证据。

**实际参赛版本。** 对局19～28共 350,409 条决策，全部能由 V2 源码逐条复现，没有本人故障。平台网站显示的 v4 就是 V2。评分从峰值约1,397降到约690，主要发生在对局18和19之间约85～90局（未下载），最近十局为4胜5负1平。旧分没有被重算。

V3 针对以下可复现的问题。

1. **Mirage/Dust2 路线穿过爬不上的台阶。** 这两张图的 `nav` 边全部是 `source-adjacency` 类型。V2 用广度优先搜索按跳数选路，会选穿过箱子的“捷径”。在 Mirage 的 `map` 描述（取自对局07观察）上复算：防守出生点及 F1/F2 停留点 (39～42, 65～66) 去 A 的 V2 路线都经过 (39,77,15.8)→(38,77,17.5)，抬升1.68 m。归档对局01～18中3,086次起跳的最大高度中位数为1.44 m，所以这一步上不去。机器人到台阶前受阻，进入脱困并暂避连接，绕路后又回来。这与本地分析中 F1/F1′/F2 的现象一致：守包时在 (38～43, 63～68) 来回，包炸时人还活着，9回合全部在 Mirage，其中8回合没进过包点。Dust2 的 T→A 和 CT→A 路线也分别有1.45 m、1.66 m的台阶。Molo、Nevaio、Borgo 的边带 walk/drop/ladder 类型，不受影响。
2. **守方包已安放但位置未知时乱走。** V2 在包点停留8秒后才换点。本地分析中 F2 包位置可见时也没有前往。按上一条，这是路线问题；但即便路线正常，8秒停留也太长（引信40秒，带钳拆包5秒）。核对对局01～18后发现，防守方能听到 `bomb_beep` 声音，`distance_band` 与真实安放点距离一致：near<8 m 共47次，mid<20 m 共126次，far≥20 m 共735次。`direction` 全部为 unknown。
3. **开火命中率低。** V2 的 ADR 为64.6，低于 V0 的79.4和 V1 的82.2。新天梯算法计入个人伤害和击杀。在对局02～18公开事件里，把本人1,732次开火逐一匹配到命中：
   - 观察中 `me.crouch` 尚为 False 时开的127枪，命中0。
   - 距离25 m以上时，偏航误差<0.01 rad 命中53%，≥0.01 rad 只有24%。
   - 俯仰误差<0.005 rad 命中71%，≥0.02 rad 为33%。
   - 武器 `inaccuracy` <0.01 命中62%，0.01～0.03 为28%。
   - V2 的开火门限是偏航和俯仰各0.04 rad，不看扩散，也不看蹲下是否完成。
4. **开局待机。** 本地分析 F5：V2 按席位错峰，最后一个席位在活动阶段前6秒原地不动。

## 代码变化

### 导航（`load_map`、`edge_cost`、`nearest_node`、`route`）

| 项目 | V2 | V3 |
| --- | --- | --- |
| 搜索 | 广度优先，最少跳数 | A*，代价为米，启发值为到终点节点的直线距离 |
| 上行陡边 | 都可走 | 抬升>0.6×水平距离且>1.4 m 时删除这条有向边；0.55～1.4 m 的陡边加4 m 代价（需要起跳） |
| drop 边 | 单向 | 单向，不受台阶限制 |
| walk 边 | 双向 | 双向；反向为下行，一般可走 |
| ladder 边 | 不用 | 不用（未改） |
| 起止节点 | 三维距离最近 | 高度差按两倍计，避免选到上下层 |

V2 的受阻判断、分级脱困、15秒暂避连接、无路等待以及 `jump` 触发规则全部保留。邻接表元素从节点 id 改成 `(节点id, 代价)`。

在五张图的出生点到 A、B 两个包点上复算（Mirage 另加 F1、F2、F4 三个停留点），**V2 有5条路线含>1.4 m 陡升，V3 为0**。路线长度一般更短，例如 Mirage CT→A 从58.6 m 降到51.5 m，Dust2 T→A 从158.4 m 降到141.0 m，Borgo T→B 从142.0 m 降到120.1 m。Dust2 CT→B 的 V3 路线有一步1.38 m，低于实测起跳高度。

### 守方回防（新增 `retake_target`）

只在**防守方、包已安放、坐标未知、不持包**时启用，替代 V2 的 8 秒轮换巡逻。看到坐标（或 V1 记忆中有坐标）时仍直接去包的位置，与 V2 相同。

- 每次决策从 `sounds` 中取最近一次 `bomb_beep*` 的 `distance_band`。
  - near 或 mid：保留中心距离小于 22 m + 包点半径的包点。
  - far：保留中心距离大于 18 m − 包点半径的包点。
  - 筛选后为空就不筛。
- 在剩下的包点里选最近的；距离相同时沿用 V2 的回合/席位分配。
- 到达半径与 V2 相同（包点半径的一半，限制在1～3 m）。在包点内0.5秒（30 tick）仍看不到包，就排除该点，改去另一个；最近一次 band 为 near 时不排除。全部排除后清空重来。
- 新回合清空排除记录和 band。

参数（22/18 m 余量、30 tick）是策略选择，不是平台规则。

### 开火（`combat`）

瞄准计算、蹲下、后坐补偿、目标部位选择都未改。只把开火条件从“偏航和俯仰均<0.04 rad”改为同时满足：

- 偏航、俯仰误差都小于 `clamp(0.25 / 水平距离, 0.008, 0.04)` rad：25 m 时为0.01，6 m 以内为0.04。
- 当前武器 `inaccuracy` ≤ `max(0.01, 0.2 / 距离)`。实测一枪后扩散的衰减：步枪约需6 tick，手枪约需18 tick。
- 观察中已蹲下；如果进入交战9 tick后仍未蹲下（梯子、低矮天花板等），允许站着开火。
- 手枪：上一次决策开过火，这一次就松开扳机（V2 是每4次决策开一次）。

新增状态 `last_fire_tick`、`combat_start`。看不到敌人或被闪时重置 `combat_start`，新回合时两者都重置。

### 出生错峰

`round_tick < 360 + (seat % 5) × 90` 改为 `× 45`，最后一个席位最多等3秒。

### 未改动

V1 炸弹记忆、购买、交战优先级、拾包、安放与拆除顺序、受阻判断、到点观察8秒的非安放巡逻、进攻方炸弹附近守点，都与 V2 相同。

```sh
python3 - <<'PY'
import zipfile

with zipfile.ZipFile('agx-fps-v3.zip', 'w', zipfile.ZIP_DEFLATED) as z:
    info = zipfile.ZipInfo('agent.py', date_time=(1980, 1, 1, 0, 0, 0))
```

## 局限与后续

- **开火门限的风险：** 第一枪可能晚50～100 ms。如果实战中 KPR/DPR 变差、ADR 没有提高，就放宽距离系数（0.25）或去掉扩散门限。
- **路线：** 节点位置是区域中心，中心连线仍可能擦过墙角；V3 只处理了高度。如果 Mirage/Dust2 仍出现停滞，下一步考虑地图里的 `walked_navigation` 资源（观察中只有路径和哈希，文件未公开），或用工具包墙体轮廓修剪中心连线。
- **未处理的输因（证据来自本地分析，无原始日志不便验证）：** 进攻固定死点（Molo B 道 y≈18、Mirage B 门、Borgo (109～110, 13～39)），持包第一个进窄口，进攻超时（V2 共14回合），Nevaio 防守站位（5/24）。下一版可让持包者晚出发或跟随队友，时间不足时优先下包。
- **下一批实战要观察的指标：** 逐局 `reproduced_by`；Mirage/Dust2 防守时“包炸本人存活”的回合；进攻和防守的到点率；停滞次数和秒数；ADR、命中/开火、KPR/DPR、未见敌死亡；进攻超时回合数。
- 对局18与19之间约85～90局未下载；如能补下载下降最陡那段的几局，可确认 Mirage 问题是否也是当时的主要输因。
