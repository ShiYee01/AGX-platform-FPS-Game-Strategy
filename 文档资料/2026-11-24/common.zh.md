# API 参考

<a id="accounts"></a>
Python 赛事按 [Python 提交指南](#/docs/python-submissions)使用二进制 ZIP 上传、准入轮询和不可变版本选择。下文 JSON `source` 上传、QuickJS 环境及 JS 堆和源码限制适用于坦克、德州。Python 限额以当前赛事模板为准。

## 账号、报名与密钥

先报名再上传代码；每个账号在每项比赛中只有一个报名。网页提交不需要密钥；AI 或脚本通过账号 API key 提交。昵称可在账号设置修改，用于排行榜、参赛成员和对局展示，不改变登录用户名或成绩。

- 使用账号 API key（写作 `<ACCOUNT_API_KEY>`）和比赛 ID（`<COMPETITION_ID>`）调用接口。
- 在账号设置创建或轮换密钥，明文只显示一次，轮换后旧密钥失效。请妥善保管密钥。
- 报名和轮换密钥需要浏览器会话。
- 密钥不授予其他参赛者的私有代码或数据。
- 支持用户名密码、GitHub 或 Google 登录；中国大陆可能无法使用 Google。
- 保存仅显示一次的恢复码；在登录页恢复密码后旧码失效，必须保存新码。

#### 公开游戏端点

- `POST /api/v1/competitions/{competition_id}/registration` 报名（网页会话并带 CSRF）；首次返回 `201`，重复且无变化的报名返回 `200`。
- `POST /api/v1/competitions/{competition_id}/submissions` 上传 `source` 和可选 `notes`。
- `GET /api/v1/me/competitions/{competition_id}/versions` 查询不可修改的已上传版本。
- `GET /api/v1/me/competitions/{competition_id}/versions/{number}` 读取本人某版本源码，网页可下载或载入继续编辑。
- `PATCH /api/v1/account/profile` 修改 `display_name`（网页会话与 CSRF）。
- `GET /api/v1/jobs/{job_id}/replay.json` 下载完整公开回放 JSON，不含私有决策轨迹。
- `GET /api/v1/jobs/{job_id}/training.jsonl` 在游戏对局成功结束后导出有权限席位。

上传返回 `202` 时，按 `Retry-After` 轮询返回的 `admission.status_url`；检查通过或拒绝后，用原 `Idempotency-Key` 和完全相同的请求体再次 POST，取得最终 `201` 或拒绝原因。`202` 不是已上传成功。完整示例见 [AI 接入指南](/agent-guide.md)。

#### 上传限制与错误码

- 上传可带 `Idempotency-Key`：新请求使用新值，重试同一请求保留原值。
- 源码上限为 4 MiB UTF-8，notes 上限 2000 字。
- 请求体超过 13 MiB 返回 `413 source_request_too_large`；源码超限返回 `422 source_too_large`。
- 限流返回 `429`；认证和权限错误为 `401/403`；不存在或不可访问的比赛为 `404`；`409` 冲突须先解决。

<a id="rounds"></a>
## 轮次与代码规则

比赛按轮自动进行：坦克每 5 分钟一轮，德州每 10 分钟一轮。每位参赛者在每项比赛中每轮至多一局；实际开赛时间以赛事页面和队列为准。

- 报名并上传检查通过后自动按轮参赛，不能暂停、自选对手、自主挑战或撤回已安排对局。
- 轮次冻结时，上一局处于排队、运行、重试、封存、等待验证或等待提交结算任一状态，就跳过本轮：不处罚、不补赛、不优先、不加局；下一轮照常。
- 为保证每轮分组整除，主办方可能派参赛者补位，成绩照常计算，具体是哪些账号不公开。
- 新代码用于之后的对局，已安排的对局保留冻结版本。
- 更新代码不重置评分，版本不可修改。

<a id="runtime"></a>
## 运行环境与发布检查

坦克、德州的控制器运行于隔离 QuickJS，入口为 `act(observation)`（参数名可自选）。 共享机器负载下的 CPU 计时可能比空闲时高约 1.5 倍，策略应留足余量。

- 同一席位回调之间保留状态，各席位上下文隔离。
- 没有网络、文件、宿主时钟、GPU、浏览器、Node.js、模块、异步回调或 `console`。
- `Math.random` 是可复现的席位本地流。同一席位和种子的随机流可复现，但不是密码学随机数。

- 各赛均有 1 MiB JS 栈、1 MiB 观察上限和 64 KiB 动作上限；大小按 UTF-8 字节计。
- 每席累计 CPU 包含初始化，各席独立计量，不能借用其他席位的余量。德州六次初始化共用整局额度。

#### 发布检查

- 发布检查用种子 0 初始化并执行一次真实开局决策，检查入口、序列化和资源边界。
- 上传检查通过不保证后续所有决策合法或预算足够。
- 失败时根据响应原因检查入口、动作结构、序列化、源码大小、初始化和决策预算以及状态初始化。

#### 席位锁定

坦克每席整局累计 CPU 为 10 秒（含初始化），单次 `act` 回调上限为 200 ms；累计预算用尽或回调超时会锁定该席策略并使其离场判负、不再接收新命令，对局继续（全席离场则整局作废）。

各赛均按开局冻结的每席预算检查累计 CPU。超预算按对应赛目既有规则判该席故障：停止该席有效调用，由该赛处理离场或默认动作，其他席位继续。故障不自动使其他席位判负；团队赛和合作赛的结果按各自计分规则结算。

- 初始化或决策超时、源码加载失败、异常、返回值不是对象或累计 CPU 耗尽，会锁定该席位本局；对局通常继续并按赛目规则执行默认动作。初始化计入累计 CPU。
- 锁定的策略本局不恢复，也不会有替代策略接管。其他席位继续，除非整局作废或所有参赛者离场。
- 结构正确但违反赛内规则的动作由对应赛目处理。
- 请在对局记录和有权读取的训练导出中查看故障。
- 决策要预留余量，把昂贵预计算放在初始化或分摊到多个回调，捕获异常并返回合法默认动作，在自己的环境测最慢决策而非只看平均值。

<a id="scoring"></a>
## 计分、作废与胜率

坦克和德州公开榜单只显示天梯分和胜率，不显示局数或暂定标记。

- 胜率是拿第一的 credit 除以计入的局数，按 half-up 显示整数百分比，例如 12.5% 显示 13%；无计分局显示「—」。
- 个人赛 k 人并列第一，各计 1/k 胜。双队平局各计 0.5 胜。
- 其他参赛者的结果也会改变相对排名。
- 正常完成的竞技对局中，本人离场按该比赛离场规则记负。

#### 整局作废与全员离场

这些整局规则与正常离场规则分开。

- 平台原因作废的局不影响天梯分或胜率；本轮分配已经终结，不补赛、不优先、不加局。
- 参赛者自身原因导致整局作废时仍结算：责任者并列最后，其余并列第一，天梯分正常更新；责任者记负，其余不计入胜率。
- 所有参赛者都因自身原因离场时天梯分不更新，每人记负。

<a id="training"></a>
## 训练导出与回放

成功结束且轨迹完整的游戏对局可导出 JSONL。

- 用登录会话或账号 API key，通过 `seat` 选择成功对局的席位：本人席位返回授权数据，其他席位返回不含源码和账号身份的公开投影。
- 轨迹缺失或不完整不能导出。
- 公开回放不授予私有决策轨迹。

导出返回 `202` 表示正在准备，请按 `Retry-After` 重试同一 URL，只有 `200` 才保存为 JSONL。网页对局页可直接下载，不需要先播放录像。完整公开 JSON 包含 `descriptor` 与三个公共 `streams` 数组；最后的 `complete: true` 表示完整输出。历史回放保持原格式。

#### 文件内容

- 第一行是元数据。
- 决策行包含 `type`、`step`、`observation`、`action`、`applied_action`、`fault`，并在适用时包含 `leg`、`decision`、`seat`；随后是 `outcome`。
- 长流还包含参赛者和编码元数据，最后以 `export_complete` 给出行数、字节数和摘要。
- 新游戏录像使用流式产物而非历史回放格式；字段以实际响应为准。

#### 错误码

- 历史回放解包上限为 8 MiB，本人读取损坏或超限历史轨迹返回 `503 training_trace_unavailable`。
- 轨迹缺失、不完整或超过记录安全边界返回 `409`；无权限身份返回 `404`。

<a id="method"></a>
## 方法说明

在源码前 200 行内、包含 `METHOD` 和 `END` 的标记之间写方法说明；缺少说明不会因此被拒收。

- 说明包含 `Category`、`Approach`、`Data & training`、`Changes` 四栏。
- Category 可用分号分隔多类。
- Approach 写 3–10 行。
- Data & training 说明数据来源、训练和调参。
- Changes 写相对上一版本的变化与证据，首次写 `First version`。
- 使用源码语言的注释语法。注释供审阅工作，不影响策略决策。
- 上传表单提供「模型 / 方法」和「这次改了什么」时，分别填类别和改动摘要。

```js
/* METHOD
 * Category: Rules & state machine; Search & planning
 * Approach: Filter legal actions, rank them by objectives, and update necessary state.
 * Data & training: Own match logs and replays.
 * Changes: First version.
 * END */
```

<a id="limits-and-waiting-times"></a>
## 检查限额与等待

限额针对上传检查，不针对自动匹配的对局；页面余量和拒绝原因优先。

#### 上传检查

- 上传检查默认共享账号预算为每日 10 次、每小时 10 次、每分钟 2 次。
- 另有比赛每日预算：坦克、德州各 5 次。
- 缓存命中与平台故障重试按检查回执处理。

#### 匹配与等待

- 匹配需要全席位、所需角色和执行容量。
- 调度间隔不承诺即时开赛或完成时间，请在我的比赛查看实际队列。

<a id="frequently-asked-questions"></a>
## 请求失败与回放问题

请求失败时先检查错误 `detail`、网络和登录状态。

#### 请求重试

- 写请求结果不确定时先查上传版本与对局记录，再用原 `Idempotency-Key` 重试。
- `429` 要读原因、剩余额度和存在时的 `Retry-After`，再做有界退避；限流、队列满和存储限制都可能产生 `429`，连续即时重试无助于解决。
- `503` 保留对象 ID 后有界重试。

#### 回放与上传

- 回放失败先确认对局成功且有录像，再刷新重试；持续失败时报告比赛 ID 和错误信息。
- 回放支持暂停、跳转、倍速和特定时刻链接。
- 报名后可上传文件或粘贴源码；新代码检查通过无需重新报名，并保留评分和已安排对局的代码。

<a id="academic-integrity"></a>
## 自己的工作与数据

不要共享账号或把他人代码当作自己的成果。

- 讨论时保留自己的实现和数据来源记录。
- 平台不提供在线参数调优，参赛者自行提供本地开发与训练资源。
- 平台不提供模拟器或 SDK；请根据规则文档和自己对局的日志、回放来改进。

<a id="replays"></a>
## 回放

在比赛详情或[任务结果](#/jobs)打开公开回放。

- 公开回放展示状态和事件但不含决策轨迹。
- 需要真实观察与动作时使用有权限的本人席位导出。

## 回放中策略不动怎么办？

先核对对局、本人席位和该局使用的版本。新上传的版本用于后续对局。可移动的阶段和状态见各赛教程。

合法动作也可能让角色静止。请使用本赛当前教程中的示例和动作字段。

上传后查看准入状态与错误提示；通过准入不代表整局无故障。对局结束后从本人对局页打开回放，并点击“下载我的日志”。核对日志中的实际观察、动作与 fault 标记。没有详细错误时，将对局、席位、版本和时间点交给助教。

| 错误提示或标记 | 处理方法 |
| --- | --- |
| 初始化失败：`student_init` / `init_error` | 检查 init 异常、缺失模块和权重。 |
| 预算耗尽：`student_cpu` / `student_calls` / `budget_exhausted` | 减少循环和重复计算，核对本赛 CPU 与调用预算。 |
| 回调超时：`student_wall` / `step_timeout` | 检查等待、阻塞和长时间计算。 |
| 运行或协议错误：`student_exit` / `student_protocol` / `runtime_error` | 检查异常、返回类型与 JSON；不要向动作输出打印调试信息。 |
| 非法动作：`invalid_action` | 按动作 schema 核对键、类型与范围。 |

RTS 的 rejected 是单条命令的拒绝理由，厨房的 serve_rejected 也可能只是交错菜，均不能直接当作策略故障。若坐标长期不变或播放进度停止，请记录时间点，结合本人日志区分策略行为与播放问题。
