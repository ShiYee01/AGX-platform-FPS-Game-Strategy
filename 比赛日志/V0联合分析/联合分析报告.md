# FPS 原版 V0：十一场联合分析与 V1 决策

> 2026-11-16补充复核：第5局百秒停滞及第10局短段停滞，存在完整me不变且持续请求转向的特征，不能直接认定为普通寻路卡墙。下文保留当时统计；更新的归因与第17局类似证据见[V1联合报告](../V1联合分析/联合分析报告.md)。

分析日期：2026-11-15，时区 Asia/Shanghai。仅分析 FPS。所有原始日志只读；没有改动现有 V1、上传比赛版本或推送仓库。

## 结论与下一步

**建议将现有 V1 作为下一轮正式实验版本上传。** 原版短暂获知炸弹位置后不保留信息的问题，在第2～11局中的4场重复出现，V1有明确的修复依据。当前V1也通过了全部11场、362,509条旧观察下的动作格式检查。

但V1只是小范围修复。联合数据中更普遍的问题是固定巡逻折返、寻路恢复和到点状态，V1没有解决。下一次独立更新应优先处理移动与稳定搜点，不宜因为团队胜负或个人击杀波动就先大改枪法。

下一批建议先固定V1跑5场，记录平台接受版本ID、切换时的1217.3分截图及之后日志；先确认运行正常、目标记忆和回防行为，再评估成绩。如果新对局没有出现短暂获知位置后坐标消失的情形，就不能据此说已验证这项修复。不要把旧观察中的动作变化当成胜率提升。

## 第一局应该怎么算

需要分开三个口径：

| 用途 | 应采用的样本 |
| --- | --- |
| 课程比赛期间的V0实验主表 | 第2～11局，共10场 |
| 赛前测试与问题发现记录 | 第1局单列，保留日志与修复证据 |
| 平台当前显示的累计成绩 | 按截图仍是11局，不能自行删掉第1局改变平台成绩 |

按用户提供的日期，第1局为11月14日赛前测试，第2～11局属于11月15日起课程窗口。该分组适用于报告与实验分析；日志本身主要记录模拟tick，没有足够的实际开赛日期字段，不能用PNG保存时间替代比赛日期。

第1局不列入课程窗口10场主表，但仍然是有效技术证据。是否有课程开赛清零、只取特定日期榜单或其他最终评分安排，需要以老师公告为准。我们不能自行重算一个“剔除首局后的平台评分”，也不能从1217.3里减掉某场的加减分来代替评级系统。

## 截图与胜率存在一个明确差异

当前总览截图显示：第31名、1217.3分、胜率55%、11局，并明确标注“成绩跨代码版本累计”。

然而，本批11份训练日志的outcome、公开事件match_end、逐场结果截图，三者一致给出：**5胜6负，胜率45.45%**。只看第2～11局则为**5胜5负，50%**。两种口径都不是55%。

因此本报告如实保留55%的页面显示值，同时以逐场核实的5胜6负/5胜5负做实验统计。原因尚未确认，不能直接断言网站一定存在某种具体错误，也不能为了匹配页面调整日志胜负。

第31名是截图时的平台排名，不是课程班级名次；55%也不能直接当成这10场正式V0样本的胜率。

“跨代码版本累计”的页面说明补充了此前未能确认的规则：更换代码版本不会让评分变成一套独立的新版本成绩。因此V1应按切换前后分组分析，不能只看累计总分判断新版本效果。

## 原版身份、日志完整性与截图核对

- 11份导出均有完整结尾，决策条数、原始决策字节数和SHA-256均与export_complete一致。
- 共362,509条决策，第2～11局共322,380条。V0逐条重算与记录动作在1e-12容差内一致。
- 本人策略故障共0次。正式10场公开事件也没有席位fault事件；赛前第1局有一次其他席位故障。
- 11场的source_hash相同。第1场与后10场的version_id不同，但行为均与保存的V0一致。
- 平台截图的v2是平台投稿版本标签，不是本地开发命名的V1。GitHub中的V1尚没有在这11场中参赛。
- 各场个人击杀、死亡、助攻及四舍五入伤害均与PNG一致；本人胜负与队伍名次一致。

## 第一场的问题是否反复出现

下表均只统计第2～11局。

| 问题 | 正式样本中的证据 | 现有V1是否处理 |
| --- | --- | --- |
| 合法看见已安放炸弹坐标后，坐标省略时没有独立记忆 | 对局2、3、4、5，共4场、5个回合、6段坐标隐藏片段 | 处理 |
| 新位置恰好被尚未结束的旧脱困覆盖 | 该特定组合未在正式10场再出现；赛前第1场确有证据 | 处理首次目标出现时的优先级 |
| 未接近原目标就因30秒计时更换包点 | 9/10场；117次切换时距旧目标仍超过5米，涉及69个回合 | 未处理 |
| 脱困反复触发、抵达后仍继续走向目标 | 共660次脱困触发，其中65次触发时距当前目标不足2米 | 未处理 |
| 出发等待 | 全部180回合均有对应席位的额外等待，约1.5～6秒，累计903秒游戏时间 | 未处理 |
| 整回合接触机会少 | 79/180回合没有开火，61/180回合存活实战期间没见过敌人 | V1只可能间接改善少量相关场景 |

117次的5米门槛是本报告的分析口径，不是官方到点规则；不能把每次换点都说成错误。660次是原版状态复算得到的“启动脱困次数”，不能全部等同于660次真实撞墙。没见敌人也可能是合理守点，需结合轨迹判断。

### 炸弹记忆：正式比赛也有证据

- 对局2第9回合：曾合法知道B点具体安放位置；坐标省略后，V0在恢复移动时改回B点中心，V1保留真实坐标。剩余约22.7秒的一个回调可直接核对。
- 对局3第12回合：合法坐标隐藏片段约0.6秒，V1仍保留真实目标。
- 对局4第23回合：坐标隐藏片段约4.4秒，V1内部维持合法记忆；但该段旧轨迹中动作并未改变，不能称为实际改进了这一回合。
- 对局5第10回合：合法位置隐藏约1.85秒，V1仍使用真实坐标，可以在接近时请求拆除；具体成功与否仍需平台裁定。

第1局最显著的“新炸弹坐标出现时正在旧脱困”的情况在正式10场没有复现，不把它写成正式样本中的高频问题。记忆缺失本身则已跨Borgo、Molo、Dust2三图重复出现。

### 移动问题比V1覆盖范围更广

额外检查了连续两次合法观察之间的位置：在角色存活、实战、确实请求移动的前提下，若相邻3tick的水平位移不超过0.005米，记为一次几乎无水平进展样本。正式10场合计约920.9秒游戏时间落入此口径，包含许多短暂停顿，不能全部当作可挽回时间。

其中有一个特别明确的长卡点：**对局5（Dust2）第11回合**，match_tick 67605～73623，连续100.3秒中，2007条观察的x/y完全不变，位置约(158.87,114.29)，同时程序一直请求移动，未见敌人。它在同一位置反复触发脱困；该回合共34次恢复尝试、没有开火。即使本队最后因防守超时获胜，这仍然是需要处理的移动问题。

这段不是购买冻结、主动守包或死亡后的中性动作。现有V1不改变它，因为该场景没有触发已知炸弹目标修复。

另一个例子是对局4（Molo）第22回合，约34.75秒持续请求移动而几乎无水平进展，位置在包点附近。说明后续需要区分：真实受阻、到点后的停留/架枪、和不断朝同一点继续前进。

91条是旧轨迹中的触发范围，不能按比例换算为胜率收益；早一个动作也可能改变真实后续过程。本检查不重新模拟移动、命中、死亡、拆除或最终赛果，因此不能宣称V1已经赢回任何一局。

综合判断：现有V1修复的问题真实存在、正式比赛中也复现，改动范围受控，可以作为下一轮参赛实验。它不足以解决十场数据暴露的主要移动问题，也没有真实V1胜率证据。

## 建议的实验安排

1. 保留当前正式10场作为V0主基线；第1场另列“赛前测试”，不删除。
2. 在AGX提交现有V1，准入通过后选择该版本；记录平台版本ID和切换时分数截图。本地命名V1不要与平台自己的v2/v3标签混淆。
3. 首批固定V1跑5场，保留本人日志、事件和结果。看运行故障、合法坐标是否保留、是否因隐藏字段丢失而改错目标，以及拆除尝试和路径。
4. 不以这5场分数涨跌单独证明效果。如果没有出现目标坐标短暂消失的机会，继续积累有关场景。
5. 下次独立更新优先修移动：长时间无进展时更换路线/恢复方式、区分抵达目标与受阻、避免机械计时推翻未完成路线。之后再单独评估末席等待。

## 数据和局限

输入来自用户指定的Downloads/FPS/对局1～对局11，每场本人训练日志、公开事件和PNG；第1场截图使用此前已提供并归档的同一截图。总览截图由用户本次提供。

所有回合号从1开始，日志索引从0开始；时长均为游戏时钟，不是CPU或实际耗时。公开事件只用于离线核对，V1检查只输入决策当时的本人合法观察。

完整性、逐场逐回合指标、坐标记忆片段和连续停滞证据保存在同目录的 `FPS-V0十一场联合核查.json`。各场原始输入、Git仓库及现有V1均未改写。
